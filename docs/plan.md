# План разработки

## Цель проекта

SkillMate - учебная платформа для обмена навыками между пользователями. Приложение помогает создать профиль, указать навыки для обучения других людей, выбрать навыки для изучения и найти партнёров по совместимости.

Продуктовый фокус проекта - довести основной путь пользователя до рабочего прототипа: регистрация или вход, поиск партнёра, предложение обмена, планирование сессии, отзыв после взаимодействия и работа с группами по интересам. Технический фокус - показать владение Angular 21, Taiga UI 4, Signal Store, mock API, guards, interceptors, тестами и CI/CD.

## Пользовательские сценарии

1. Регистрация и вход в личный кабинет: пользователь создаёт аккаунт или входит по mock-данным, получает mock JWT-сессию и видит только свои данные.
2. Поиск партнёра по навыкам: пользователь ищет анкеты, фильтрует по категории, сортирует по совместимости, рейтингу или имени и выбирает подходящего человека.
3. Предложение обмена и учебная сессия: пользователь открывает анкету партнёра, выбирает тему, дату, время и длительность, отправляет предложение и видит сессию в ближайших занятиях со статусом ожидания.
4. Группы, материалы и отзывы: пользователь создаёт группы по интересам, приглашает партнёров из анкет, добавляет материалы, удаляет участников или материалы и оставляет оценку с отзывом о партнёре.

## Риски

1. Несовместимость Angular 21, Taiga UI 4 и тестового окружения - фиксировать версии в `package-lock.json`, чаще запускать `npm run lint`, `npm run test`, `npm run e2e` и `npm run build`.
2. Mock API может изменить данные во время ручной проверки - хранить стабильные seed-данные в `mock/db.json`, перед сдачей проверять демо-аккаунты и ключевые сценарии.
3. Taiga UI может быть использована слишком формально - применять компоненты в реальных интерфейсах: кнопки, loader, notification, badge, progress, card, textfield/select.
4. Не хватит тестов на важные сценарии - покрыть Jest auth/guards/utils/components, а Playwright сценарии login, регистрацию, CRUD/группы, фильтрацию, отзывы и приглашение в группу.
5. Проблемы с деплоем и Lighthouse ближе к дедлайну - заранее проверить production build, настроить CI/CD, добавить публичный URL в README и оптимизировать первый экран.
