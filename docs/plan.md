# План разработки

## Цель проекта

SkillMate - Angular-приложение для поиска партнёров по обмену навыками. Пользователь создаёт профиль, указывает навыки, которым может учить, и навыки, которые хочет получить. Система помогает найти совместимых людей, предложить обмен, запланировать учебную сессию, оставить отзыв и отслеживать прогресс.

Проект делается как семестровый прототип: основная ценность находится в понятной Angular-архитектуре, mock API, авторизации, управлении состоянием, тестах и готовом сценарии демонстрации на защите.

## Пользовательские сценарии

1. Вход и персональный профиль: пользователь входит по демо-аккаунту, видит свои навыки, цели и прогресс.
2. Поиск партнёра: пользователь фильтрует партнёров по навыку или категории, сортирует по совместимости, рейтингу или имени.
3. Обмен и расписание: пользователь отправляет предложение обмена и создаёт учебную сессию с партнёром.
4. Группы и материалы: пользователь создаёт группу по интересам и добавляет полезную ссылку для участников.

## Этапы разработки

| Срок | Задача |
| --- | --- |
| До конца апреля | Angular 21 workspace, routing, core/shared/features структура, auth flow, базовые компоненты, формы профиля и расписания, mock db |
| 1-2 неделя мая | Signal Store, интеграция с json-server, guards, interceptors, loading/error состояния, поиск, фильтрация, сортировка |
| 3 неделя мая | Unit-тесты на Jest, Playwright-сценарии, линтеры, README, CI pipeline |
| До конца мая | Production build, деплой, Lighthouse, подготовка 5-7 минутной демонстрации |

## Риски

1. Несовместимость Angular 21 и сторонних пакетов - фиксировать версии в `package-lock.json`, проверять `npm run build` после крупных изменений.
2. Mock API недоступен во время демо - запускать `npm run mock:api` отдельно или `npm run dev`, держать демо-данные в `mock/db.json`.
3. Недостаточно явная архитектура на защите - придерживаться `core / shared / features`, держать бизнес-логику в сервисах и Signal Store.
4. Слабое покрытие тестами - тестировать чистые функции, pipe, auth guard, сервисы и ключевые пользовательские сценарии.
5. Проблемы с деплоем - заранее выбрать Vercel или GitLab Pages, добавить публичную ссылку в `README.md`, проверить production build и Lighthouse.
